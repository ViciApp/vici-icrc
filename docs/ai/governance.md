# Governance

What an agent may do in this repo without asking, what it must ask for, and which page to update for which kind of change. The truth hierarchy is in [`AGENTS.md`](../../AGENTS.md#6-governance) and the [standard](https://github.com/AntonioVentilii/officina/blob/main/standards/code.md#truth-hierarchy).

## Why this repo is sensitive

The minter is the minting account of the VICI ledger on mainnet (`canister_ids.json`): whatever it mints is new supply. A bug in a cap, a rate limit, a counter or a lock is inflation that cannot be undone, and the 1,000,000,000 VICI commitment in [`TOKENOMICS.md`](../../TOKENOMICS.md) is held only by the reserve caps (see [`domain.md`](./domain.md)). Upgrades restore the whole state from stable memory, so a type change that does not decode makes the upgrade trap.

Nothing deploys on merge; deploys are manual `npm run deploy:prod` or `reinstall:*:prod` runs by the owner. A tag `v*` publishes the release assets (`minter.wasm.gz`, `minter.did`, ledger and index) that vici-app pins and installs (`VICI_ICRC_VERSION` in its `scripts/build/download.vici_icrc.minter.sh`).

The repository is public. A suspected security or money bug is told to the owner in private and never written in a PR, an issue, a commit message or a review comment.

## Protected and generated paths

| Path                                                                                   | Why                                                                                 | Rule                                                                            |
| -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `src/minter/minter.did`                                                                | Generated by `npm run did` (candid-extractor on the wasm)                           | Never hand-edit; regenerate and commit with the API change                      |
| `src/minter/src/state.rs`, persisted types in `model.rs`                               | Decoded from stable memory on every upgrade                                         | Ask first; follow [change-persisted-type](./workflows/change-persisted-type.md) |
| `src/minter/src/lib.rs` lifecycle hooks, the `Arg` type                                | What an install or an upgrade does to the state                                     | Ask first; see [upgrades](./domain.md#upgrades)                                 |
| `canister_ids.json`                                                                    | Mainnet canister ids                                                                | Ask first                                                                       |
| `dfx.json`, the ledger-suite release in it and in `scripts/download.ledger.sh`         | Which ledger and index wasm get installed                                           | Ask first                                                                       |
| `scripts/build.*.args.sh`, `scripts/check.canister.installed.sh`                       | Init and upgrade arguments, including token name, decimals, fee and minting account | Ask first; see [canister-args](./workflows/canister-args.md)                    |
| `scripts/init.reserves.sh`                                                             | Reserve caps and daily budgets on mainnet                                           | Ask first; numbers are business decisions                                       |
| `.github/workflows/**`, `.github/actions/**`, `.github/dependabot.yml`                 | CI integrity and release assets                                                     | Ask first; `ci(...)` PRs only                                                   |
| `Cargo.toml` `[workspace.lints]`, `clippy.toml`, `rustfmt.toml`, `rust-toolchain.toml` | The lint and format contract                                                        | Ask first; never loosen to get green                                            |
| `Cargo.toml`, `Cargo.lock`, `package.json`, `package-lock.json` dependencies           | New dependencies need the owner's approval                                          | Ask first; see [dependency-bump](./workflows/dependency-bump.md)                |

| `.dfx/`, `out/`, `target/`, `.env`, `**/declarations/`, `node_modules/`                | Build and deploy output                                                             | Never commit                                                                    |

## Allowed without asking

- Edit `src/minter/src/services/**`, `api/**`, `guards.rs` and non-persisted types in `model.rs`, with tests, as long as no rule in [`domain.md`](./domain.md) changes.
- Edit `docs/ai/**`, `AGENTS.md`, `README.md`, `src/minter/README.md`, and scripts outside the protected rows above.
- Run `npm ci`, `npm run format`, `npm run lint`, `npm run did`, `npm run build`, `cargo test`, and `npm run deploy` against a local replica.
- Push a branch and open a PR.

## Never without an explicit ask

- Merge a PR, enable auto-merge, queue a PR, push to `main`, push a `v*` tag, force-push.
- Run anything with `--ic` or `DFX_NETWORK=ic`: `npm run deploy:prod`, any `reinstall:*:prod`, `scripts/init.reserves.sh` against mainnet, or `dfx canister call` on a mainnet canister.
- Change a number that moves supply or its pace: reserve caps, daily budgets, rate-limit defaults, `REBALANCE_INTERVAL`, the window lengths, token decimals or fee. Propose, do not pick.
- Change what a mint checks, the order it checks it in, what it records, or who may call it. Propose the change with its effect on each rule of [`domain.md`](./domain.md).
- Relax a guard, or change who may call an endpoint, as a side effect of another change.
- Remove or rename a Candid method, field or `MinterError` variant: vici-app installs the minter from this repo's release and other tools call it.
- Add a dependency, a crate to the workspace, a canister or a top-level folder.
- Commit a secret, a private key, a PEM file, an identity or a real reserve principal.

## Risk levels

The PR template asks for one; use this scale.

| Risk   | Examples                                                                                         | What it needs                                                      |
| ------ | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| Low    | Docs, comments that explain why, tests, a script outside the protected rows                      | The normal gates                                                   |
| Medium | Anything under `src/minter/src/` that does not touch a mint, a cap, a guard or a persisted type  | Unit tests for the behaviour, `minter.did` regenerated if it moved |
| High   | Minting, locks, idempotency, caps, rate limits, guards, persisted types, lifecycle hooks, CI     | The owner's go-ahead first, and the upgrade proven on a replica    |
| High   | Canister arguments, `canister_ids.json`, `init.reserves.sh`, the ledger release, large deletions | The owner's go-ahead first; nothing is run against mainnet         |

## Meta-update map

A PR that changes one of these updates the matching page in the same PR (rule 13 of the standard).

| Change                                                    | Update                                                                                 |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| New shared function, constant, type or script             | [`reusability.md`](./reusability.md)                                                   |
| New pattern, or an anti-pattern removed or found          | [`patterns.md`](./patterns.md)                                                         |
| A unit, a fee, a cap, the mint order, a ledger call       | [`domain.md`](./domain.md), and `src/minter/README.md` concepts                        |
| What an install or an upgrade does, or a persisted format | [`domain.md`](./domain.md#upgrades) and [`patterns.md`](./patterns.md#stable-state)    |
| New file, module or dependency direction                  | [`structure.md`](./structure.md) and the code tree in `src/minter/README.md`           |
| New or changed endpoint                                   | `src/minter/README.md` API reference, and `minter.did` via `npm run did`               |
| The token economy or the reserve plan                     | `TOKENOMICS.md`, `TLDR.md`, and the header of `scripts/init.reserves.sh`               |
| New test location, helper or command                      | [`testing.md`](./testing.md)                                                           |
| New CI job, gate, script or PR convention                 | [`pr-and-ci.md`](./pr-and-ci.md)                                                       |
| A recurring kind of change with no recipe yet             | a new page in [`workflows/`](./workflows/) and the index in [`README.md`](./README.md) |
| A policy here                                             | this page, and `AGENTS.md` if the summary changes                                      |

Every link stays relative and every file it names exists: check them before opening the PR.
